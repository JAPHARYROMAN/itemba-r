# Inventory Pages — Definitive Improvement Plan

Repo root: `C:/projects/Actual Projects/itemba-r`
Scope: six pages under `frontend/src/app/(dashboard)/operations/` — products, product-categories, units, inventory-balances, inventory-movements, stock-adjustments.

> Generated by a multi-agent audit (per-page audit → adversarial grounding verification → cross-cutting analysis → synthesis). Every finding was checked against the actual source before inclusion.

---

## 1. Executive Summary

The seven highest-leverage moves, in plain language:

1. **Fix the silent data-loss bugs first.** Three pages display fields the API never sends (inventory-balances/movements: `productCode`, `reorderLevel`, `lastMovementAt`), one filter returns the wrong rows (`isActive='false'` coerces to `true` in two category DTOs), and one approval flow throws away the mandatory rejection reason. These are correctness blockers that make operator-facing signals quietly lie. Each is a small backend select/DTO/wiring change.

2. **Make inventory pages actually show stock.** Products has no on-hand/below-reorder column despite the backend computing it; inventory-balances has no "Available" (on-hand − reserved) column despite the math being trivial. These are the single highest-value gaps for pages whose job is inventory.

3. **Connect the chain.** A posted adjustment writes movements that carry `referenceType/referenceId`, but the UI severs every link: you cannot go balance → movements → adjustment, and stock-adjustment lines are a black box (only a count is shown). Wire the existing provenance into drill-through navigation and a detail drawer.

4. **Fix one shared Modal to fix accessibility everywhere.** The shared `Modal` has no focus trap, no initial focus, no focus restoration — a P0 a11y defect inherited by all five pages with dialogs. One fix at the source.

5. **Stop the KPIs from lying.** Almost every page computes "Active / Low Stock / Pending" counts over the 20-row current page, some honestly labelled "(page)", one (categories) not labelled at all. Drive these from real totals (groupBy or `limit:1` total reads).

6. **Build a pricing/stock hygiene worklist.** `priceSource` (MISSING/FAMILY_DEFAULT/OVERRIDE) is computed per product but there's no filter to act on it; family "missing price" counts are shown with no way to fix them. Turn computed insight into actionable, filterable lists.

7. **Converge on the design system.** Six pages split into two table idioms, hand-roll status pills five different ways, and copy-paste formatters and the "Access Restricted" block six times. Pick one list idiom, route all pills through `StatusBadge`, and centralize formatters/permission chrome.
