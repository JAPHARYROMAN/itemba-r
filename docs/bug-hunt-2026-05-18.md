## 1. Security & Tenant Isolation

### 1.1 Active-Sessions IDOR — `findByUser` accepts any userId (HIGH)
[`active-sessions.service.ts:45-60`](backend/src/modules/active-sessions/active-sessions.service.ts)
Service method takes a `userId` argument and returns sessions for that user with **no ownership check**. The `/my` controller passes the current user correctly, but the service itself is unprotected — any other module/internal caller (or a future controller that forwards a body param) can enumerate sessions for any user. Add `user: AuthUser` param and assert `userId === user.id || hasPermission('active_sessions.manage')`.

### 1.2 Active-Sessions metadata leak in `findOne` (MEDIUM)
[`active-sessions.service.ts:62-68`](backend/src/modules/active-sessions/active-sessions.service.ts)
`findOne(id)` fetches by ID first, then runs the company-access check. Metadata (IP, userAgent, device, timestamps) is already loaded by the time the check throws. Scope the initial `findFirst` to accessible companies.

### 1.3 JWT strategy doesn't pin algorithm (MEDIUM)
[`auth/strategies/jwt.strategy.ts:30-34`](backend/src/modules/auth/strategies/jwt.strategy.ts)
No explicit `algorithms: ['HS256']` (or whichever is in use). Passport-jwt's default is permissive; on a future rotation to RS256 (or vice versa), this becomes a downgrade vector. Pin it.

### 1.4 `data-isolation-issues` admin module is unscoped (LOW, but principle violation)
The findOne / list endpoints don't filter by tenant/company. Permission-gated, so risk is bounded — but this is a multi-tenant ERP and even admin views should be tenant-aware.

### 1.5 `2fa/admin/reencrypt-legacy` has no rate-limit or idempotency guard (MEDIUM)
[`auth.controller.ts:220-232`](backend/src/modules/auth/auth.controller.ts)
A user with `users.assign_roles` who calls this twice could race the encryption pass. Add `@Throttle({ ttl: 3600000, limit: 1 })` plus an idempotency check in the service.

### 1.6 CORS with `credentials: true` + env-driven origin (MEDIUM, config-dependent)
[`main.ts:29-32`](backend/src/main.ts)
If `CORS_ORIGIN` is ever set to a wildcard or has whitespace issues during split, browsers will allow credentialed cross-origin requests from unintended subdomains. Validate origins at boot — reject `*` or `*.foo.com` patterns when credentials are on.

**Strong points observed:** `CompanyScopeService` is used correctly in most finance/sales modules; argon2 password hashing with constant-time comparisons; refresh-token rotation and revocation present; auth-route throttling configured.

## 2. Business Logic, Transactions, Races

### 2.1 `DocumentNumberSequencesService.nextNumber()` — read-then-write race (CRITICAL)
[`document-number-sequences.service.ts:46-54`](backend/src/modules/document-number-sequences/document-number-sequences.service.ts)
```ts
const seq = await this.findOne(id);
const nextNum = (seq.currentNumber ?? 0) + 1;
...
await this.prisma.documentNumberSequence.update({ where: { id }, data: { currentNumber: nextNum } });
```
Two concurrent calls both read N, both write N+1 → **duplicate document numbers**. `EntityCodeGeneratorService.next()` already uses atomic `{ increment: 1 }` at line 61 — same pattern needs to apply here.

### 2.2 Supplier-invoice payable/match numbers use `Date.now()` (HIGH)
[`supplier-invoices.service.ts:23-29`](backend/src/modules/supplier-invoices/supplier-invoices.service.ts)
`AP-${year}-${Date.now().toString(36)}` collides if two approvals fire in the same millisecond. Route through `EntityCodeGeneratorService.next()` instead.

### 2.3 `GoodsReceivedNote.post()` is not transactional (HIGH)
[`goods-received-notes.service.ts:67-72`](backend/src/modules/goods-received-notes/goods-received-notes.service.ts)
Status flips to `POSTED` before the inventory movement is created. If the second step fails (network/DB error), the GRN is "posted" but stock never moved. Wrap in `prisma.$transaction([...])`.

### 2.4 `InventoryMovementsService` transaction wrapping is implicit (MEDIUM)
[`inventory-movements.service.ts:229-236`](backend/src/modules/inventory-movements/inventory-movements.service.ts)
The `FOR UPDATE` lock is only held for the full operation if the caller passes `tx`. Otherwise the service wraps a new transaction. Easy to misuse — a caller doing multi-step work outside a tx loses the lock between calls. Make the `tx` param required or document the contract loudly.

### 2.5 `ExternalPaymentsService.confirmTrusted()` not idempotent (MEDIUM)
[`external-payments.service.ts:175-209`](backend/src/modules/external-payments/external-payments.service.ts)
A network retry from the client double-stamps `confirmedAt` and emits duplicate audit events. Accept an idempotency key (or short-circuit if `status === SUCCESS`).

### 2.6 `dateTo` filter off-by-one (MEDIUM)
Multiple services: [`audit-logs.service.ts:237`](backend/src/modules/audit-logs/audit-logs.service.ts) and similar in expenses, journal-entries.
`new Date('2026-05-18')` is midnight UTC. Users mean "include all of May 18". Records timestamped 23:59 are silently excluded. Normalize: when only a date is supplied, use end-of-day for `dateTo`.

### 2.7 Supplier-invoice approval flow lacks an explicit transaction around invoice→payable (MEDIUM)
[`supplier-invoices.service.ts`](backend/src/modules/supplier-invoices/supplier-invoices.service.ts) (approval flow, ~line 246+)
If payable creation fails after the invoice is marked APPROVED, the invoice is "complete" with no backing payable. Wrap in `$transaction`.

## 3. Frontend

### 3.1 Root layout reads `localStorage` in inline script (CRITICAL)
[`frontend/src/app/layout.tsx:14-22`](frontend/src/app/layout.tsx)
The theme-bootstrap script accesses `localStorage` at script-evaluation time. On SSR there is no `localStorage` — first paint crashes or produces a hydration mismatch. Guard with `typeof window !== 'undefined'` or move to a no-FOUC pattern that checks the cookie server-side.

### 3.2 Accounting-engine pages fetch with no `companyId` (CRITICAL)
`accounting-locks/page.tsx:10`, `audit-adjustments/page.tsx`, `bank-reconciliations/page.tsx`, `posting-rules/page.tsx`, `posting-runs/page.tsx` all call backend without scope params:
```ts
fetch('/api/backend/accounting-locks')
```
Depending on backend defaults this either returns the calling user's company data only (fine) or returns *everything across tenants* (catastrophic). Either way the contract is undefined — make scope explicit on every call.

### 3.3 Unguarded `localStorage` access in delete handlers (CRITICAL on SSR / safe in browser)
[`logistics/drivers/page.tsx:116`](frontend/src/app/(dashboard)/logistics/drivers/page.tsx) and other logistics pages
`Authorization: Bearer ${localStorage.getItem('accessToken')}` is read inside an event handler — server can't render this path, so the crash risk is low, but the pattern is wrong: bypasses the central API client and never refreshes a stale token. Route through the existing API client.

### 3.4 Zero `error.tsx` files across the entire `app/` tree (HIGH)
Any unhandled render error nukes the whole segment. Add `error.tsx` at least at the dashboard root and at top-level group boundaries.

### 3.5 `westsides/quick-sale` double-submit possible (HIGH)
[`westsides/quick-sale/page.tsx:347-389`](frontend/src/app/(dashboard)/westsides/quick-sale/page.tsx)
`charge()` flips a `submitting` flag but the button isn't disabled and there's no in-flight guard against re-entry from a second click. Disable the button on `submitting` and short-circuit at entry.

### 3.6 Auto-refresh starts before hydration in westsides cockpit (MEDIUM)
[`westsides/page.tsx:188-210`](frontend/src/app/(dashboard)/westsides/page.tsx)
30s timer can fire with an empty/wrong `companyId` between mount and hydration. Gate the timer behind the `hydrated` flag.

### 3.7 Silent error swallow in accounting engine summary (LOW)
[`accounting-engine/page.tsx:34`](frontend/src/app/(dashboard)/accounting-engine/page.tsx)
`.catch(() => {})` leaves the user with zeros and no signal that the backend is down. Surface a toast or banner.

### 3.8 Login form has no client validation (LOW)
[`(auth)/login/page.tsx`](frontend/src/app/(auth)/login/page.tsx)
`noValidate` + no manual checks → empty submits hit the API. Add minimal email/password checks.

## 4. Schema, FKs, Indexes, Migrations

### 4.1 25+ FK relations omit `onDelete` (HIGH)
Citations include `database/prisma/schema.prisma:10411, 10554, 10692, 10747, 12008, 12035, 12062-12064, 12092, 12128-12129, 12203-12204, 12228-12230, 12257, 12281-12282, 12339, 12396, 12444, 12494, 12546`. Prisma defaults to `NoAction`, which translates to PostgreSQL `RESTRICT` — production deletes will fail with FK violations. Especially impactful for `ExternalPayment.company`, `IntegrationConnection.provider`, `ApiKey.apiClient`, `OfflineSyncBatch.user`. Decide intent per FK (`Cascade`, `SetNull`, `Restrict`) and declare it.

### 4.2 Destructive migrations with no archival (HIGH)
`database/prisma/migrations/20260424153733_v2_production_schema/migration.sql` and `20260430144135_w1_pos_removal_sales_order_enrichment/migration.sql` drop POS tables and several columns (`entity`, `address`, `registrationNumber`, `tin`, `isActive`) with no `INSERT INTO archive_*` step. If a rollback is ever needed, the data is gone.

### 4.3 Missing indexes on common-query FKs (MEDIUM-HIGH)
`Expense` ([schema.prisma:2065-2089](database/prisma/schema.prisma)) has `createdById`, `approvedById`, `paidById` with no index. "Find all expenses approved by user X" scans the table. Same audit applies to other large operational tables.

### 4.4 Missing composite indexes on hot paths (MEDIUM)
- `Expense (companyId, status, approvedAt)` — approval-queue queries
- `JournalEntryLine (companyId, accountId, createdAt)` — GL drill queries
- `*OrderLine (parentId, lineNumber)` — line ordering

### 4.5 Mixed UUID/CUID ID strategy (MEDIUM)
Most models use `@default(uuid())`, but `RefreshToken`, `TwoFactorBackupCode`, `Notification`, `AlertRule`, `AnalyticsSnapshotRun` use `@default(cuid())`. Pick one and document; mixed usage trips integration code that assumes a fixed format.

### 4.6 `AnalyticsSnapshotRun.companyId` is nullable (MEDIUM)
[`schema.prisma:10009`](database/prisma/schema.prisma) — must logically belong to a company. Queries that join on companyId silently drop NULL rows. Make it required and backfill.

### 4.7 Soft-delete is opt-in per query (MEDIUM)
35+ models have `deletedAt` but services don't uniformly filter `deletedAt: null`. Centralize via a Prisma extension/middleware or audit each list endpoint.

## 5. Cross-cutting (Validation, Errors, Tests, Performance)

### 5.1 `any` DTOs everywhere (HIGH)
282+ instances of `dto: any` / `body: any` / `query: any` / `user: any` in service signatures (e.g., [`posting-runs.service.ts:13`](backend/src/modules/posting-runs/posting-runs.service.ts), [`period-close.service.ts:44`](backend/src/modules/period-close/period-close.service.ts)). Same in some controllers using `@Body() body: { comment?: string }` or `@Body() body: any` (alert-events, audit-adjustments, bank-reconciliations, bi, construction-projects, crop-seasons). `ValidationPipe` cannot validate `any` — invalid input reaches Prisma. Replace with class-validated DTOs.

### 5.2 Pagination params unbounded (MEDIUM, DoS vector)
[`posting-runs.service.ts:13-15`](backend/src/modules/posting-runs/posting-runs.service.ts) parses `page`/`limit` with `Number()` and no clamp. Client sends `page=9e9` → `skip = ~1.8e10`. Add `Math.min(limit, 200)` and reject `page > 10_000`.

### 5.3 N+1 queries (MEDIUM)
- [`account-resolver.service.ts:72-80`](backend/src/common/services/account-resolver.service.ts) — `resolveMany` issues 2 finds per role serially. Batch by `code/subtype IN (...)`.
- [`bi.service.ts:38-47`](backend/src/modules/bi/bi.service.ts) — KPI snapshot map per company. Single `findMany` then in-memory join.

### 5.4 Path-traversal / unsafe storage defaults (HIGH on misconfig)
[`documents.service.ts:33-38`](backend/src/modules/documents/documents.service.ts), [`backup-run.handler.ts:45-52`](backend/src/modules/job-worker/handlers/backup-run.handler.ts), [`data-export.handler.ts:437`](backend/src/modules/job-worker/handlers/data-export.handler.ts) — if `STORAGE_LOCAL_PATH` / `BACKUPS_DIR` / `BACKUP_STORAGE_PATH` is unset, code silently falls back to `process.cwd()`. A bad deploy writes backups/exports into the app directory. Fail fast at boot if these envs are missing in production.

### 5.5 Test coverage crisis (HIGH)
319 backend services, only 42 `*.spec.ts` files. Untested critical modules include `posting-runs`, `period-close`, `financial-reports`, `tax-filing-engine`, `depreciation`, `journal-entries`. These are exactly the modules whose bugs become regulatory issues.

### 5.6 Inconsistent list-endpoint response shapes (MEDIUM)
- `{ items, total, page, limit }` — posting-runs, period-close
- `{ data, total, page, limit, totalPages }` — bank-accounts
- `{ recentInsights, openIssuesCount, ... }` — bi (no pagination at all)

Pick one shape and refactor.

### 5.7 `as any` enum casts (MEDIUM)
[`bi.service.ts:15, 21, 27`](backend/src/modules/bi/bi.service.ts) — `status: 'OPEN' as any` defeats the enum type-check. A typo will silently match nothing. Import the enum and use it.

### 5.8 Hardcoded `take: 100` (MEDIUM)
[`bi.service.ts:64-68`](backend/src/modules/bi/bi.service.ts) — `inventory_summary` ignores supplied paging and always returns 100. Either honor pagination or remove the param from the contract.

### 5.9 5xx logs may include sensitive stack trace context (LOW)
[`common/filters/http-exception.filter.ts:47-50`](backend/src/common/filters/http-exception.filter.ts) — logs full stack on 5xx. Usually fine, but ensure exception messages never embed account/token values; add a scrubber.
